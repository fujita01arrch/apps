## わかったこと

1. **単純な「新→旧」の関係ではない**。両者は同じベースから分岐しており、それぞれ独自に持つ機能がある。

2. **Gemini改良版（ローカル）が追加している機能**
   - タスクボード（アイゼンハワーマトリクス：緊急×重要の4象限）
   - タスクの分類（カテゴリ／タグ）管理機能
   - 顧客に紐づかない「一般タスク」機能
   - マトリクスの緊急・重要判定基準を設定画面で変更できる機能

3. **現行デプロイ版にあった `deleteCustomer` 関数**
   - コード上は存在するが、**どのボタンからも呼び出されていない（デッドコード）**。つまり現行デプロイ版でも実際には顧客削除はUI上できない状態だった。
   - 藤田さんの指示により、「引継ぎ完了・離脱」タブ内でのみ有効な削除ボタンとして新規に実装した（他のステージでは表示されない）。

4. その他の差分（`handleGoogleLogin`/`handleLogout`の分離など）は実装の書き方の違いのみで、機能的な差はなし。

5. Firebase設定（`projectId: hikitugi-539c8` 等）は両者で完全一致。同じバックエンドを参照している。

## 追記（動作確認で発見した既存バグの修正）

ローカルサーバーで実際に開いたところ、「Loading...」から進まない不具合を確認しました。原因はGemini改良版に元からあったロジックの並び順の誤りです。

- **バグの内容**：ログイン画面を出す条件（`if (!user) return ログイン画面;`）より先に、「ログイン後のデータ取得中」判定（`if (authChecking || isLoading) return Loading画面;`）が来てしまっていた。`isLoading`はログイン後のFirestore読み込みでしか`false`にならないため、**未ログインの人は永久にLoading画面から進めない**状態だった。
- **現行デプロイ版は影響なし**：`authChecking`→`!user`（ログイン画面）→`isLoading`の順で正しく実装されていたため、この不具合はGemini改良版で新たに発生したもの。
- **修正内容**：判定の順序を `authChecking` → `!user`（ログイン画面） → `isLoading` の3段階に戻した（`index.html` に反映済み）。
- ローカルHTTPサーバー（`localhost`）上でログイン画面まで正常に表示されることを確認済み。
