# 商談音声 自動リネーム・Drive移行・Notta連携

Androidスマホの標準ボイスレコーダーで録音した商談音声を、Googleカレンダーの予定と突き合わせて自動リネームし、Googleドライブへ保存、同時にNottaへ共有するための仕組み。

このディレクトリは **Google Apps Script** のソースコードです。GitHub Pagesでは公開されません（`apps/` 配下の静的HTMLアプリとは無関係）。[script.google.com](https://script.google.com/) 上に新規プロジェクトを作り、ここにあるファイルの内容をコピー＆ペーストして使います（`clasp` を使える場合はpushでも構いません）。

全体設計の背景・判断根拠は `/root/.claude/plans/android-google-google-notta-bubbly-balloon.md`（このセッションのプランファイル）を参照してください。

## 全体の流れ

```
Android端末(Tasker) --新規録音を検知-->
  1. HTTP POSTでこのWeb Appに録音開始時刻を送る
  2. Apps Script が Googleカレンダーの前後30分の予定を検索し、
     タイトル中の「◯◯様」からリネーム後のファイル名を判定して返す
  3. Taskerが返却されたファイル名で端末上のファイルをリネーム
  4. Tasker標準の「Google Drive Upload」アクションで
     判定結果に応じたDriveフォルダへアップロード
  5. 同じ（リネーム後の）ファイルをNottaアプリへ共有インテントで自動送信
```

## すでに自動で完了している準備

- Googleドライブに保存先フォルダを作成済み:
  - `商談音声/01_完了` → https://drive.google.com/drive/folders/1JjQmz4VrEmUwXdn4bfwsPEyPaHzpA-3b
  - `商談音声/02_要確認` → https://drive.google.com/drive/folders/18lmoKOYLTvkkMI8oAXjZur4h7j3Kdp_1
- Web App用の合言葉（`SHARED_SECRET`）も生成済み。チャット側の回答に記載しているので、そちらを使ってください（秘密情報のためgitリポジトリには載せていません）。下記「2. 合言葉（SHARED_SECRET）を設定」の手順で使用する。

## セットアップ手順（ここからは手元のPC・スマホでの操作が必要です）

### 1. Apps Scriptプロジェクトの作成
1. ブラウザで https://script.google.com/ を開く（Googleアカウントでログイン済みであること）
2. 左上の「新しいプロジェクト」をクリック
3. 開いたエディタに、デフォルトで書かれている `function myFunction() {...}` を全部削除し、`Code.gs` の内容を貼り付け
4. 左側のメニューから、時計アイコンではなく「プロジェクトの設定」（歯車アイコン）をクリック
5. 一番下の「'appsscript.json' マニフェストファイルをエディタで表示する」にチェックを入れる
6. 左メニューに `appsscript.json` が表示されるので開き、内容をこのリポジトリの `appsscript.json` の内容に置き換えて保存（Ctrl+S）
7. 左メニューの「エディタ」（`< >` アイコン）に戻り、上部のプロジェクト名（「無題のプロジェクト」）をクリックして「商談音声リネーム自動化」など分かりやすい名前に変更

### 2. 合言葉（SHARED_SECRET）を設定
1. 「プロジェクトの設定」（歯車アイコン）を開く
2. 一番下までスクロールし「スクリプト プロパティ」→「スクリプト プロパティを追加」
3. プロパティ: `SHARED_SECRET`　値: 上記の生成済みの合言葉（`(SHARED_SECRETの値はチャットの回答を参照)`）を貼り付け
4. 「スクリプト プロパティを保存」をクリック

### 3. 動作確認（デプロイ前）
1. Googleカレンダー（このスクリプトが見るのはログイン中のGoogleアカウントの「メインカレンダー」）に、今の時刻に近い時間で「テスト太郎様と商談」のようなタイトルの予定を仮作成
2. Apps Scriptエディタに戻り、上部の関数選択ドロップダウンで `testProcessTimestamp` を選択し、「実行」ボタン（▷）をクリック
3. 初回は「承認が必要です」という画面が出るので、Googleアカウントを選択 →「Google では、このアプリを確認していません」という警告が出た場合は「詳細」→「（プロジェクト名）に移動」→「許可」で承認
4. 「実行ログ」に `{"matched":true,"newFileName":"..."}` のような結果が表示されれば成功。テスト用のカレンダー予定は確認後に削除してよい

### 4. Web Appとしてデプロイ
1. 右上の「デプロイ」ボタン →「新しいデプロイ」
2. 「種類の選択」の歯車アイコン →「ウェブアプリ」を選択
3. 「実行するユーザー」: 自分（あなたのアカウント）
4. 「アクセスできるユーザー」: 全員
5. 「デプロイ」をクリックし、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/.../exec` の形式）をメモ・コピーする
6. このURLと合言葉は、この後Taskerの設定で使うので、メモ帳等に控えておく（第三者に共有しないこと）

### 5. デプロイ後の動作テスト
**Web AppのURLをデプロイできたら、そのURLをこのチャットに貼ってください。curlでのテスト実行はこちらで代行します。**（自分で試す場合は下記コマンドのURL部分を書き換えて実行してください）
```bash
curl -X POST "<デプロイしたWeb AppのURL>" \
  -H "Content-Type: application/json" \
  -d '{"secret":"(SHARED_SECRETの値はチャットの回答を参照)","timestampMillis":1735795200000}'
```
`timestampMillis` はミリ秒のUNIXタイムスタンプ。実施時は、テスト用カレンダー予定の時刻に近い値に書き換えて確認する。

## Android端末（Tasker）側の設定

これ以降は物理的にスマホを操作する作業のため、Claudeが代行することはできません。以下の手順で進めてください。

追加インストールするアプリは **Tasker のみ**（Google Playで購入・買い切り・アカウント不要）。Google Driveアップロードは Tasker本体標準搭載の「Google Drive Upload」アクションを使うため、Autosync等の同期専用アプリは不要。

### 準備
1. Google Playストアで「Tasker」を検索し購入・インストール
2. 使用機種の標準ボイスレコーダーで実際に1件録音し、ファイラー（「ファイル」アプリ等）やTasker内のファイル選択画面から、その録音ファイルの保存先フォルダのパスを確認する（機種依存。Pixelの「Recorder」は非公開領域に保存され、通常のファイラーからは見えない場合があるため要注意。見えない場合は別モデル・別の録音アプリの利用も検討）
3. Tasker初回起動時に、通知・ファイルアクセス等の権限を許可

### プロファイル作成
1. Taskerを開き、「プロファイル」タブ →「+」→「イベント」→「ファイル」→「ファイル作成」を選択
2. 上記2で確認した録音保存フォルダのパスを指定
3. 作成されたタスクに、以下のアクションを順に追加:
   1. **変数設定**: 新規ファイルの作成時刻（ミリ秒）を変数（例 `%file_time`）に取得
   2. **HTTP Request**（POST）: URLに手順4でメモしたWeb App URLを指定。ボディに `{"secret": "(SHARED_SECRETの値はチャットの回答を参照)", "timestampMillis": %file_time}` のようなJSONを設定し、Content-Typeを `application/json` に
   3. レスポンスのJSONから `matched` と `newFileName` を変数に取り出す（Taskerの「JavaScriptlet」または「変数を設定」＋JSON解析機能を使用）
   4. **If** `matched` が `true` の場合:
      - ファイルを `newFileName + 元の拡張子` にリネーム（「ファイル」→「ファイルをリネーム」）
      - **Google Drive Upload** アクションで、アップロード先フォルダを `商談音声/01_完了` に指定してアップロード
   5. **Else**（`matched` が `false`）:
      - ファイル名はそのまま
      - **Google Drive Upload** アクションで、アップロード先フォルダを `商談音声/02_要確認` に指定してアップロード
   6. どちらの場合も、最後に **Send Intent** アクション（`ACTION_SEND`, MIMEタイプ `audio/*`, 対象パッケージ: Nottaアプリ）で、同じファイルをNottaへ共有

Tasker側の細かい画面操作（アクション名・UIの位置）はTaskerのバージョンで多少異なります。詰まった箇所があれば、その時の画面のスクリーンショットや状況を教えてください。一緒に確認します。

## 既知の注意点

- Web Appは非エンジニアの端末からHTTPで呼べるよう「アクセスできるユーザー: 全員」で公開する必要がある。認証は `SHARED_SECRET` の一致確認のみなので、URLと合言葉は第三者に漏らさないこと。
- Notta側には「Googleドライブフォルダを自動監視して取り込む」機能や、確実に使える公開APIが確認できなかった（2026年8月時点）。そのため本設計では、Nottaアプリへの「共有」操作をTaskerで自動発火させることで代替している。Nottaのアプリ仕様変更で動作しなくなる可能性がある点は留意すること。
- `◯◯様` 抽出の正規表現（`extractClientName_`）は、実際のカレンダー予定タイトルの実例に応じて調整が必要になる場合がある。
